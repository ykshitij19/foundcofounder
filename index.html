Context

What is casting, and who is this for?

Casting means selecting actors for ads, films, and web series. A brand tells a casting agency what they need — the agency finds matching actors and sends their photos/videos to the client.

ARC is built for casting agencies — the people managing hundreds of actors and fulfilling multiple briefs daily. They are our primary user and product champion.

  • 1
    Client gives briefe.g. "Female, 20–25, bubbly, North Indian look for ad shoot"
  • 2
    Agency finds matching actorsFrom their database of hundreds or thousands of actors
  • 3
    Agency sends photos/videosFormatted as a deck or PPT, delivered via WhatsApp or Drive
  • 4
    Client gives feedback → repeatThis loop happens 2–5 times per casting. Every loop = manual rework.

The Problem

9 steps. All manual. Every time.

Every single casting goes through this 9-step process. When the client asks for more options — it starts again from step 5.

01
Actor sends data
Photos, videos, PDFs via WhatsApp. Unstructured. No fixed format.
02
Agency stores it
In Drive folders or hard disks. Different people, different systems.
03
Excel sheet
Name, age, gender tracked. But media is NOT inside the Excel.
04
Brief arrives
Client sends requirements. The process begins.
05
Filter Excel
Age + gender filters only. Vibe? Look? Pure guesswork.
06
Manual folder search
Hunt through Drive for every matched actor. One by one.
07
Download files
Download photos and videos manually. Repeat 15–20 times.
08
Re-upload & send
Build PPT or Drive folder. Send via WhatsApp to client.
09
Client says "more" → repeat 5–8
Every iteration = full manual rework. No state saved anywhere.
Storage Chaos

Thousands of actors, each with multiple files — photos, videos, PDFs — scattered across different Drive folders, hard disks, and WhatsApp chats. No structure, no single place to look.

Three-Tool Nightmare

Excel for data. Drive for files. WhatsApp for sending. Three separate tools that don't talk to each other, stitched together by human memory and manual copy-paste.

Iteration = Start Over

Every time the client says "send more" or "make it younger," the agency redoes the entire process from scratch. There is no saved state, no shortcut. Pure repetition.

4 Hours. Every Casting.

One brief can consume 3–4 hours end to end. Agencies handle multiple briefs per week. This is dozens of hours of pure manual overhead — exactly the business ARC eliminates.

Portfolio Building Pipeline

One master template. Infinite profiles.

The architecture is already built. Deploying a new actor profile is a config file change — not a build from scratch. Every profile is live in under 30 minutes, hosted for free.

How the template engine works
🏗️
Master Architecture (Fixed — Never changes)
Full website codebase — layout, components, routing, hosting pipeline, GitHub Actions CI/CD. Built once, reused for every single actor. Zero rebuild per profile.
⚙️
Config File (Changes per actor)
Name, photos, videos, bio, skills, social links, colors, fonts, layout variant. One JSON/YAML file per actor. Fill it in → push to GitHub → site is live.
🚀
Auto-Deployment Pipeline
GitHub push triggers Vercel deploy. Profile is live on a Vercel subdomain within minutes. No manual hosting steps. No server management.
Casting agencies need uniformity — all free profiles look the same template. That's a feature, not a limitation. Agencies can preview actors consistently.
